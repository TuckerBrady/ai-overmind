# v4.0.1 — MIGRATION FIXES (patch release, ships first)

**Status:** fully specified, ready to build. Both defects were reported by an
independent Overmind's full-release audit of v4.0.0 and confirmed by live tests
in the paste-based runtime. Both are recoverability defects, not security
findings; each is roughly one instruction to close.

## GAP 1 — the migration has no backup step

The v4.0.0 migration replaces `Project Instructions.md` with the 8-line
paste-wrapper stub, and instructs generating BOOT.md from the existing block —
*generate*, never "copy verbatim." In a paste-based runtime the platform's
instruction field cannot be read by any tool, so `Project Instructions.md` is
the ONLY on-disk copy of a team's boot layer. An LLM paraphrase replaces the
original with nothing to diff against: silent, unrecoverable normalization of
customized boot layers.

**Fix (confirmed writable in the paste runtime):** BEFORE the stub replaces the
file, write BOTH backups, and say so in the migration offer text:

- `Project Instructions.md.bak` beside the original — the copy a panicking
  human finds in three seconds unaided. **This one is blocking.**
- `_Archive/Project Instructions.<date>.md` — dated, so it survives a RE-RUN
  migration (a second run overwrites the first `.bak`; the dated copy costs
  one mkdir and is insurance against the migration eating its own backup).

**The migration ABORTS — not warns — if either write fails.** In a paste
runtime there is no second chance.

**Recovery net worth one test during the build:** a paste-runtime session
transcript may retain the pasted boot text (transcript-reading tools exist in
that runtime). If confirmed, a pre-fix migration disaster is recoverable after
the fact. Unverified; close before shipping the release notes claim.

## GAP 2 — CLAUDE.md written with no read-before-write

Roster step 3 and the firmware member-folder path both write the thin CLAUDE.md
wrapper unconditionally. A member folder that is also a code repo, or that
already holds a hand-written CLAUDE.md, gets clobbered silently. Plausible
layout, not a corner case — the one destructive path in v4.0.0 with no prose
guard at all.

**Fix — the 4-check guard, in order (confirmed by simulation):**

1. `CLAUDE.md` absent → write freely. Done.
2. Contains `@BOOT.md` already → already migrated. **No-op, and say so.**
   (Idempotency rule: a migration that is not safe to re-run WILL be re-run.)
3. Exists, no import, and content **byte-matches the shipped stub template** →
   our own leftover; safe to replace.
4. Exists, no import, unrecognized content → **the collision. Never
   overwrite.** Back it up (`CLAUDE.md.bak`), show the human the collision,
   and PREPEND the `@BOOT.md` import line to the existing file — the import
   is additive; the human's content has no reason to die for it.

Check 3's byte-compare is the load-bearing detail: it is what separates "our
own leftover" from "somebody's work."
