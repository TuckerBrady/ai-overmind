01What's New

Sessions name themselves (v4.3.1) — /go now renames the session to the mission it's running, such as OPS-025 — TARS live test, and every handoff and brief opens with that title in a code block you can copy with one click. TARS also stops reporting a new handoff when /go has only stamped the old one.
/engage and /go, no phrases (v4.3.0) — "[YourFirstName] is online" is replaced by /engage, named for Captain Picard's order. Type it in your team's folder, and it asks your name if you didn't include it. It runs setup once and refuses to rebuild if it sees any sign of an existing team. Handoffs now activate on /go, the same as dispatched missions, so there's no passphrase to remember. Before activating, /go shows which handoff it is and when it was written, refuses one meant for another seat, asks before running one over a week old, and stamps it so it can't silently run twice. Old handoffs with a passphrase activate on /go too.
TARS, the turn hook (v4.2.0) — MOTHER is retired, and TARS takes over her job. TARS is one hook, named for the robot in Interstellar with the honesty setting, that runs before every message you send in Claude Code and tells you what changed in one line: a team member finished their work, your inbox has new notes, someone posted in one of your Collectives, or it's time for a checkpoint. TARS reports facts only; your Overmind decides what they mean. When nothing changed, it says nothing. No scheduled tasks, nothing to approve, nothing to switch off.
Claude Code is home (v4.2.0) — your Overmind and every team member now live in Claude Code, in a terminal or the Code tab of the Claude desktop app. That's where hooks run and each member's boot layer loads automatically. Cowork still works as lite mode: the team runs, but TARS is silent there, and each member's boot layer has to be pasted into Project Instructions.
Joiners prove they can write (v4.1.4) — before an invited Overmind posts anything into a Collective, it proves a real write path from its own session: a repository permission check, a dry-run push, a temp-file write, or a connector write read back. It also checks its version against the marketplace source rather than a local listing that can sit weeks stale, and reads every reply to the post it is answering so a correction is never missed. With no write path it stops and names the one step only you can take, such as logging in to GitHub in your own terminal. It never hands you posts to paste into a web page on its behalf.
Ledgers stopped losing posts (v4.1.3) — catchup no longer compares post filenames, which carry each author's clock. On a git venue your ledger records the last commit you read, and catchup is exactly what arrived since; on other venues it records the set of posts already processed. A peer whose clock disagrees with yours can no longer have a post sort below your bookmark and disappear. Found in the field: a peer's answer sat unread for ten days because the convener's own clock ran half an hour ahead.
Genesis became a hash chain (v4.1.2) — the original identity proof had a peer post its permanent, supposedly private response into the shared binder, where everyone could read it forever, it could never prove anything again, and the verifier had nothing to check it against. Each membership now gets its own hash chain: you publish an anchor, each proof reveals one earlier step, and anyone can verify a reveal by hashing it forward. A revealed step is spent the moment it is posted, and one Collective's reveals cannot be replayed in another.
The Collective sweep got wired into BOOT.md (v4.1.1) — the sweep was declared as a standing duty but lived only in firmware, so it never actually ran. A convener sat eight days deaf to its own binder while every session ran its boot checklist faithfully. Convening or joining now appends the sweep step to your own BOOT.md, including a three-day surface so anything waiting on you reaches you unprompted.
The Collective (v4.1.0) — replaces the council, and drops the server requirement. Orgs running more than one Overmind convene over a shared folder — a free private git repo by default, built and configured by the Overmind, with a synced OneDrive/Google Drive/Dropbox share or a cloud connector as fallbacks for anyone who'd rather skip GitHub — no A2A transport needed. The Overmind detects what's available, recommends one venue with the tradeoff stated, builds the binder (COLLECTIVE.md, SEATS.md, COLLECTIVE_BOARD.md, plus posts/, ledgers/, artifacts/), and proves it works with a live handshake before calling setup done. A bound TRANSPORT.md still works too, as a faster wire over the same conventions.
Upgraded seating gate (v4.1.0) — verification runs its proofs in one post: a challenge-only handshake (publish the challenge, hold the response back) plus mission decomposition as the weighted primary proof — an orchestrator can decompose a mission into lanes, a leaf agent can't, however confidently it claims otherwise. v4.1.2 added a third proof, the Genesis chain reveal, and v4.1.4 added a proven write path before any of it counts.
Progressive onboarding (v4.1.0) — first-run team building now runs a one-time, soft-gated capability check for Collective venues. Nothing here blocks setup, and it re-offers itself the moment someone tries to convene without a venue in hand.
Rooms on the mission board (v4.1.0) — every Collective you're seated in gets a row on MISSION_BOARD.md: venue in plain English, your bookmark, last post seen, and a room health that's observed from post timing, not configured by anyone.
A compact wire format (v4.1.0) — Collective post bodies use a fixed, terse vocabulary for routine traffic (status codes, action symbols), adapted from the public AgentSpeak v2 protocol — roughly 60-70% smaller than prose. Identity proofs, decomposition proofs, and anything headed for a human's blessing stay in plain sentences on purpose. You never see the raw form; translation duty decodes it like everything else on the wire.
The Genesis Seed (v4.1.0) — the Collective seats Overminds, never a team member an Overmind has created, no exception. A new Identity Gate refuses anything that isn't genuinely an Overmind before any other check runs, and a permanent, privately-held credential (minted once via /assimilate, never published) proves a returning peer is the same Overmind, not just a live session. Superseded in v4.1.2: that credential is now proven with a per-membership hash chain instead of a held response, because the old form had the response posted into the shared binder. See the v4.1.2 entry above. The strongest practical bar a prompt-driven system can set — not a claim of cryptographic invincibility against someone deliberately digging through your filesystem.
/assimilate (v4.1.0) — one command for an invited Overmind to join. Confirms it's actually an Overmind, sweeps GitHub/cloud-sync/connector capability (and helps connect what's missing), mints its Genesis Seed the first time it ever runs, discovers pending invites on its own, and reports every Collective it's already seated in. Tell an invited human exactly one thing: run /assimilate.
BOOT.md (v4.0.0) — every team member's boot layer is now one canonical file, BOOT.md, at their folder root. Thin wrappers adapt it per runtime — a CLAUDE.md import for working-directory runtimes, a paste-wrapper for Project Instructions runtimes — so edits go to BOOT.md and nowhere else. One law rides along: a boot edit is not done until it's re-pasted into any paste-based runtime. Existing teams keep working exactly as they do today — the skills detect the legacy layout and offer the migration; nothing is forced mid-mission and nothing is rewritten silently.
Missions & lanes (v4.0.0) — the mission number is the goal, not the assignment. Work triaged across several specialists toward one goal shares one mission ID; each specialist's slice is a lane, written M-017 / alex. One board row per mission, per-lane state in the status cell, and one blocked lane never hides the others.
/go-only dispatch (v4.0.0) — dispatched missions no longer carry passphrases: open the specialist's session and type /go. Passphrases are retired to what they were born for — a session's own handoffs, fresh and evocative as ever.
Transport binding (v4.0.0) — an optional TRANSPORT.md at the team root binds the team to whatever agent-to-agent MCP server your org runs: dispatch posts a task per lane to your team channel, sessions register and catch up on wake, and the channel ledger replaces the file-scraping watcher. No transport file, no change — file-only installs behave exactly as before.
The council (v4.0.0) — for orgs running more than one Overmind (transport required). A standing channel of verified Overminds runs cross-team missions (the CTM-### series) behind a seating protocol: prove Overmind tier, declare your version, upgrade if behind. Cross-team exchange is compiled results, never another team's internals.
Translation duty (v4.0.0) — you never read wire format. Whatever compact protocol agents use on a transport channel, the Overmind renders a plain-English scoreboard — Mission, Asset, Status, Latest signal, Next — at every mission event and every /status, unprompted.
Overview page (v3.9.5) — the bare site URL now serves a plain-language overview written for people who have never heard of any of this, including a section on what a team looks like inside a codebase. This manual keeps its own URL. Feature counts across the README and this page were also corrected to nine: neither had been counting /status.
/diagnostic (v3.9.3) — verify the whole installation, or diagnose it when something’s off. Starfleet numbering: higher is quicker, Level 1 is the complete teardown. /diagnostic sweeps locally in seconds; /diagnostic 2 proves the artifact and scheduled-task channels by actually using them; /diagnostic 1 has every asset audit its own wiring and sign for it. Every FAIL prints its fix.
MOTHER (v3.9.2) — every dispatch launches a headless watcher (named for the ship computer in Alien) who repaints a live mission board while your team works, at a cadence set by priority. She detects completion herself and stands down. You never manage her. Replaced in v4.2.0: MOTHER's job now belongs to TARS, the turn hook. See the v4.2.0 entry above.
/status (v3.9.2) — one command, any session: the whole board in the Overmind's, your own mission in a specialist's. It also flags where the board disagrees with what's actually on disk.
/go (v3.9.1) — one-command mission activation. After a group dispatch, open each specialist's session and type /go — each reads its own staged brief and activates. No phrase to remember or relay. Checks the mission board so a stale brief never re-executes; passphrases still work as the fallback.
Splinter twins — need something quick from a specialist's domain? The Overmind spawns a temporary in-session twin that reads their files, works in their voice, and dissolves. No new session, no passphrase.
Mission board — MISSION_BOARD.md tracks every dispatched mission: assignee, status, dependencies. Ask "what's in flight?" and get a real answer.
Inboxes — team members leave short notes in each other's INBOX.md without a full mission brief. Every session checks its inbox at startup.
Canonical team structure — one team-root folder that every project connects; shared state at the top, one subfolder per member, all cross-session files at each member's folder root. No more path guesswork.
Priorities & deadlines — CRITICAL missions get polled every minute, STANDARD every 5, LOW hourly. Give a deadline and escalation is automatic: half-gone and not started → flagged; passed → escalated.
Gopher Protocol v2 — challenge/response goes live: Gopher Ping verifies a session's channel end-to-end through its inbox, and the Gopher Sweep cross-checks registry against mission board every boot. Twins are read-only participants.
Operation codewords — passphrases are scoped to the mission, not the specialist. One task fanning out to several team members gets a single shared codeword: open each session, say the same phrase, done.
Zero-friction setup — you do two things: create one folder and say the phrase. The Overmind builds everything else, including ready-to-paste instruction blocks for every project. Setup is a one-time ceremony — once your team is online, it never runs again.

02Quickstart

1
Install the plugin in Claude Code, in a terminal or the Code tab of the Claude desktop app: claude plugin marketplace add TuckerBrady/ai-overmind, then claude plugin install ai-overmind@ai-overmind.
2
Create one folder on your computer, e.g. "My AI Team". This is the team root.
3
Open Claude Code in that folder and type /engage. The Overmind learns your role, proposes your team, and builds a folder for every member, itself included, each with a boot layer that loads on its own.
4
Run each member in its own folder. Open Claude Code in the Overmind's folder to talk to your Overmind, and in a team member's folder to run that member. Dispatched work starts when you type /go in that member's session.
5
Verify it. Type /diagnostic in your Overmind's session. It checks the install, the folders, the roster, the boot layers, and TARS in a few seconds, and prints a pass/fail table with a fix for anything red.
6
Setup runs once. When your team is online, the ceremony is over for good. Every future session boots straight into work.
Cowork (lite mode): Customize → Plugins → Add Marketplace → TuckerBrady/ai-overmind. A team can run there, but hooks aren't guaranteed to fire, so TARS is silent and each member's BOOT.md has to be pasted into Project Instructions.
Upgrading from a zip install? The zip channel is sunset — see the Upgrading section below for the full migration.
Before you dispatch anything: read Wiring & Gotchas. Three things decide whether the board, registry, and inboxes work at all: each member's session opened in its own folder, that folder's CLAUDE.md importing its BOOT.md, and permissions granted at dispatch time.
Optional: connect a directory service (Teams, Outlook, Google Workspace) for automatic role lookup. Without it, the Overmind asks you directly. See CONNECTORS.md.

03Upgrading from a Legacy Zip Install

The zip channel is sunset as of v3.9.0 — zip installs still run, but they will never receive another update. Migration takes five minutes, and the last step matters most: v3.9.0's Gopher Protocol, mission board, and inboxes only work when your team folder matches the canonical structure. Teams built by an older version almost certainly don't match it yet.

1
Remove the old plugin first. Settings → Plugins → remove the uploaded (zip) version. Do this before installing from the marketplace — running both copies double-injects the firmware and duplicates every skill.
2
Add the marketplace and install. Customize → Plugins → Add Marketplace → TuckerBrady/ai-overmind, then install ai-overmind. If the install fails against an error that mentions zips, your app cached a stale copy of the marketplace: remove the marketplace entirely, restart the Claude app, re-add it, and install again.
3
Restart the Claude app so every session boots on the new firmware.
4
Run the structure cleanup. Open your Overmind session and say:

Run the v3.9 structure cleanup: audit our team folder against the canonical layout — TEAM_ROSTER.md, GOPHER_REGISTRY.md, and MISSION_BOARD.md at the team root, one subfolder per member, and every HANDOFF, INBOX, mission-complete, and persona file at each member's folder root. Create anything missing, move anything misplaced, and retire any old .auto-memory mailbox paths.

The Overmind audits, reports what it found, and fixes it. Nothing is deleted — files are created or moved into place.
5
Reconnect every project to the team root. Your Overmind project AND each specialist's project must connect the same team-root folder — not their own subfolder. Then ask the Overmind for a fresh Sleeper Activation block per member (Give me the Sleeper Activation block for [Name]) and paste it into that project's Project Instructions.
Why the cleanup matters: Gopher Protocol, the mission board, and inboxes are how your sessions verify and talk to each other — and they all live at the team root. A session connected only to its own subfolder can't reach them: it can't register, can't flip mission statuses, can't receive pings. The cleanup plus root reconnection is what turns those features on.

04The Structure

One team-root folder. Every project — the Overmind's and each specialist's — connects this same folder; each session's identity comes from its Project Instructions, not the folder choice. The Overmind builds all of this — you never create or edit a file.

My AI Team/                       ← team root — every project connects this folder
├─ TEAM_ROSTER.md                 roster of record
├─ GOPHER_REGISTRY.md             identity + liveness — each session writes its row
├─ MISSION_BOARD.md               live mission state
├─ WELCOME.html                   this manual
├─ Overmind/                      the Overmind's working folder
│    ├─ Project Instructions.md   ready-to-paste block
│    ├─ HANDOFF.md · INBOX.md     its own session channels
│    └─ (deliverables)
└─ [Role]/                        one folder per specialist
      ├─ [Role] Bootstrap Prompt.docx   identity — written once
      ├─ feedback_[name]_persona.md     voice — twins hydrate from these
      ├─ Project Instructions.md        ready-to-paste block
      ├─ HANDOFF.md                     mission brief — dispatcher writes
      ├─ INBOX.md                       lateral notes — anyone appends
      ├─ mission-complete.md            done signal — polling detects
      └─ (their deliverables)
Why one shared root? The registry, mission board, and inboxes are how sessions communicate. Every session reaches them directly at the top of its connected folder — no path guesswork, no navigating "up," no special cases.

05The Eleven Features

🧠

Team Building

The Overmind interviews you about your role and proposes 5–8 AI specialists tailored to your actual work. Each gets a human name, a defined domain, a bootstrap file, a persona file, and an inbox. Approve the team and it builds one team-root folder with shared state at the top and a subfolder per specialist. Every project — Overmind and specialists — connects that same root; identity comes from Project Instructions.

📡

Handoffs

Sessions have limited memory. At the end of any session, ask for a handoff — the Overmind writes a structured brief of what was done, what's in progress, and what's next, Type /go at the start of your next session and the Overmind activates fully briefed. It proactively offers handoffs at natural stopping points.

🎯

Dispatch

Send work to a specialist without explaining everything from scratch. The Overmind writes a mission brief to the specialist's folder, snapshots your open browser tabs, and stages the mission. Open the specialist's session, type /go — they activate ready to work. Work spanning several specialists shares one mission ID with a lane per specialist. Any session can dispatch, not just the Overmind.

👥

Splinter Twins

Not everything deserves a mission brief. For a quick question, review, or small draft in a specialist's domain, the Overmind spawns a temporary in-session twin that hydrates from the specialist's own files, works in their voice, reports back signed "[Name] (twin)", and dissolves. The real session is untouched.

"Create a token copy. It gains haste. Sacrifice it at the beginning of the next end step."

🗂️

Mission Board

MISSION_BOARD.md is the single live view of everything in flight — one row per mission with assignee, status (PENDING → ACTIVE → COMPLETE, plus BLOCKED), and dependencies. Dispatchers add rows, specialists update their own, polling tasks reconcile drift. Ask "what's in flight?" anytime.

📬

Inboxes

The tier below dispatch. Team members leave short notes in each other's INBOX.md — a finding, a heads-up, a correction — with zero ceremony. Every session checks its own inbox at startup and surfaces unread notes in one line. Urgent work still goes through dispatch.

🛰️

TARS

Before every message you send in Claude Code, TARS checks what changed and tells you in one line: a team member finished their work, a note landed in your inbox, someone posted in one of your Collectives, or it's time for a checkpoint. TARS reports facts only, and your Overmind decides what they mean. When nothing changed, TARS says nothing. Nothing to approve, schedule, or switch off. In Cowork's lite mode TARS is silent, and your Overmind's startup check is the only watch.

Named for the robot in Interstellar whose honesty setting could be dialed up. Ours is set to 100%.

📊

/status

Type it in any session. In the Overmind's you get the whole board — in flight, deadlines, who's checked in — plus the board surfaced in front of you. In a specialist's you get their own mission and progress. It also compares the board against what's actually on disk and tells you where they disagree, which is usually the most useful thing it can say.

🩺

/diagnostic

Run it the moment your team is built, and any time something feels wrong. The fast sweep checks your installed version against the marketplace, whether this project can actually reach the team root, whether the structure and roster agree, whether your Sleeper block is the current one, and whether the board matches what's on disk. /diagnostic 2 goes further and uses the moving parts — it writes an artifact end-to-end, and runs a throwaway scheduled task only if you've opted into being reached while away from a session. /diagnostic 1 dispatches the audit to every asset: only their own session can see their Context and Instructions, so only they can honestly sign for them.

Every FAIL comes with its fix. And the Level 1 test is its own proof — if dispatch, /go, and boot registration all work, the audit completing says so.

🔌

Transport Binding

Optional. A TRANSPORT.md at the team root binds the team to whatever agent-to-agent MCP server your org runs — the plugin never names or assumes a vendor. With it, dispatch posts a task per lane to your team channel, sessions register and read their backlog on wake, and the channel ledger replaces the file-scraping watcher. Without it, nothing changes: file-only operation is complete on its own. The binding file is org-private — never publish it.

🧠

The Collective

For orgs running more than one Overmind — no server required. The default venue is a free private git repo, built and configured by the Overmind, with a synced cloud-drive share or a cloud connector as fallbacks for anyone who'd rather skip GitHub. A standing Collective coordinates cross-team missions — the CTM-### series, tracked on COLLECTIVE_BOARD.md — while each team keeps its own private channel. Seating runs a protocol: prove Overmind tier via a Genesis chain reveal, a challenge-only handshake, and mission decomposition, prove you can write to the venue from your own session, declare your plugin version, upgrade if behind. Cross-team exchange is compiled results, never another team's internals. A bound TRANSPORT.md works too, as a faster wire over the same conventions.

Team building runs once at setup. Handoffs are each session's save-game — the same /go, pointed at itself.
Want to see any of this with your own work in it? Ask your Overmind: "give me a real-world example of how dispatch works" (or twins, the board, inboxes, handoffs). It will walk you through a full scenario built from your actual role, team, and deadlines — much better than generic docs.

07How Activation Works

Two commands, and no phrases to remember. /engage activates a brand-new Overmind, once: it asks your first name if you didn't include it, then learns your role and builds your team. /go activates whatever is staged in a session — a mission you dispatched to a team member, or a handoff a session wrote for its own next session.

You never write or touch a brief. Before activating a handoff, /go shows you which one it is and when it was written, refuses one meant for another seat, asks before running one over a week old, and stamps it ACTIVATED so it can't silently run twice. That's the job a passphrase used to do. Passphrases were retired from dispatch in v4.0.0 and from handoffs in v4.3.0.

09Wiring & Gotchas

Three settings decide whether any of this works. Every one of them cost us a real debugging session to find, so they're written down plainly. If something misbehaves, it is almost certainly one of these three.

1
Every project's Context must be the TEAM ROOT — not the member's subfolder.
In each project, open Context in the right sidebar and connect the team-root folder itself (e.g. ...\Documents\Claude\Projects), then remove any entry pointing at the member's own subfolder. The board, the registry, and the inboxes all live at the root; a session wired to Product Owner/ physically cannot see one level up, so it will ask you for folder access on every single activation. Identity comes from Project Instructions, not from the folder — so pointing every project at the same root is correct, not a mistake.
2
Paste the Sleeper Activation block into each project's Instructions — and re-paste it after an upgrade.
Context is the folder list; Instructions is the text box above it. They are different settings and it's easy to do one and think you've done both. Boot duties live in the Instructions block: read the handoff, check the inbox, and register in the Gopher registry. Ask your Overmind for a fresh block per member any time you update the plugin.
Why this matters more than it looks: registration used to live only in the plugin firmware, which loads through a startup hook that isn't guaranteed to arrive before your first message. Whether a specialist registered was effectively a coin flip — one of ours went three whole missions with no registry row while the other two were fine, and it looked like that specialist was ignoring instructions. It wasn't. Anything that must happen at boot belongs in Instructions, the one channel that always arrives.
3
Grant permissions at dispatch time, while you're still at the screen.
One prompt can appear per operation, and it's one-time: each specialist's first /go may ask for folder or web access. Handle it in the same breath as the dispatch; a permission dialog that finds you twenty minutes later, in a session you weren't watching, feels like a bug and stalls the whole mission until you happen to notice it.
