01What's New in v3.9.x

/go (v3.9.1) — one-command mission activation. After a group dispatch, open each specialist's session and type /go — each reads its own staged brief and activates. No phrase to remember or relay. Checks the mission board so a stale brief never re-executes; passphrases still work as the fallback.
Splinter twins — need something quick from a specialist's domain? The Overmind spawns a temporary in-session twin that reads their files, works in their voice, and dissolves. No new session, no passphrase.
Mission board — MISSION_BOARD.md tracks every dispatched mission: assignee, status, dependencies. Ask "what's in flight?" and get a real answer.
Inboxes — team members leave short notes in each other's INBOX.md without a full mission brief. Every session checks its inbox at startup.
Canonical team structure — one team-root folder that every project connects; shared state at the top, one subfolder per member, all cross-session files at each member's folder root. No more path guesswork.
Priorities & deadlines — CRITICAL missions get polled every minute, STANDARD every 5, LOW hourly. Give a deadline and escalation is automatic: half-gone and not started → flagged; passed → escalated.
Gopher Protocol v2 — challenge/response goes live: Gopher Ping verifies a session's channel end-to-end through its inbox, and the Gopher Sweep cross-checks registry against mission board every boot. Twins are read-only participants.
Operation codewords — passphrases are scoped to the mission, not the specialist. One task fanning out to several team members gets a single shared codeword: open each session, say the same phrase, done.
Zero-friction setup — you do two things: create one folder and say the phrase. The Overmind builds everything else, including ready-to-paste instruction blocks for every project. Setup is a one-time ceremony — once your team is online, it never runs again.
Marketplace delivery — this repo is a Claude plugin marketplace. Install once, updates ship automatically. The legacy zip channel is sunset as of this release — marketplace only.

02Quickstart

1
Install the plugin from the marketplace: Customize → Plugins → Add Marketplace → TuckerBrady/ai-overmind, then install ai-overmind.
2
Create one folder on your computer — e.g., "My AI Team". This is the team root. Every project you create will connect this same folder.
3
Create a Cowork project, connect that folder, and say [YourFirstName] is online
4
That's it. The Overmind learns your role, proposes your team, builds the entire structure, and walks you through bringing each specialist online — one clear step at a time, with ready-to-paste blocks it already wrote for you.
5
Setup runs once. When your team is online, the ceremony is over for good — every future session boots straight into work. From here, you're just building the relationship.
Upgrading from a zip install? The zip channel is sunset — see the Upgrading section below for the full migration, including the structure cleanup that Gopher Protocol needs.
Optional: connect a directory service (Teams, Outlook, Google Workspace) for automatic role lookup. Without it, the Overmind asks you directly. See CONNECTORS.md.
Why Project Instructions? Cowork SessionStart hooks are not guaranteed to inject into context before the first message. The passphrase/handoff system must live in Project Instructions to be reliable at boot. The plugin firmware handles on-demand features (handoffs, dispatch). Both work together — Project Instructions for startup, firmware for everything else.

03Upgrading from a Legacy Zip Install

The zip channel is sunset as of v3.9.0 — zip installs still run, but they will never receive another update. Migration takes five minutes, and the last step matters most: v3.9.0's Gopher Protocol, mission board, and inboxes only work when your team folder matches the canonical structure. Teams built by an older version almost certainly don't match it yet.

1
Remove the old plugin first. Settings → Plugins → remove the uploaded (zip) version. Do this before installing from the marketplace — running both copies double-injects the firmware and duplicates every skill.
2
Add the marketplace and install. Customize → Plugins → Add Marketplace → TuckerBrady/ai-overmind, then install ai-overmind. If the install fails against an error that mentions zips, your app cached a stale copy of the marketplace: remove the marketplace entirely, restart the Claude app, re-add it, and install again.
3
Restart the Claude app so every session boots on the new firmware.
4
Run the structure cleanup. Open your Overmind session and say:

Run the v3.9 structure cleanup: audit our team folder against the canonical layout — TEAM_ROSTER.md, GOPHER_REGISTRY.md, and MISSION_BOARD.md at the team root, one subfolder per member, and every HANDOFF, INBOX, mission-complete, and persona file at each member's folder root. Create anything missing, move anything misplaced, and retire any old .auto-memory mailbox paths.

The Overmind audits, reports what it found, and fixes it. Nothing is deleted — files are created or moved into place.
5
Reconnect every project to the team root. Your Overmind project AND each specialist's project must connect the same team-root folder — not their own subfolder. Then ask the Overmind for a fresh Sleeper Activation block per member (Give me the Sleeper Activation block for [Name]) and paste it into that project's Project Instructions.
Why the cleanup matters: Gopher Protocol, the mission board, and inboxes are how your sessions verify and talk to each other — and they all live at the team root. A session connected only to its own subfolder can't reach them: it can't register, can't flip mission statuses, can't receive pings. The cleanup plus root reconnection is what turns those features on.

04The Structure

One team-root folder. Every project — the Overmind's and each specialist's — connects this same folder; each session's identity comes from its Project Instructions, not the folder choice. The Overmind builds all of this — you never create or edit a file.

My AI Team/                       ← team root — every project connects this folder
├─ TEAM_ROSTER.md                 roster of record
├─ GOPHER_REGISTRY.md             identity + liveness — each session writes its row
├─ MISSION_BOARD.md               live mission state
├─ WELCOME.html                   this manual
├─ Overmind/                      the Overmind's working folder
│    ├─ Project Instructions.md   ready-to-paste block
│    ├─ HANDOFF.md · INBOX.md     its own session channels
│    └─ (deliverables)
└─ [Role]/                        one folder per specialist
      ├─ [Role] Bootstrap Prompt.docx   identity — written once
      ├─ feedback_[name]_persona.md     voice — twins hydrate from these
      ├─ Project Instructions.md        ready-to-paste block
      ├─ HANDOFF.md                     mission brief — dispatcher writes
      ├─ INBOX.md                       lateral notes — anyone appends
      ├─ mission-complete.md            done signal — polling detects
      └─ (their deliverables)
Why one shared root? The registry, mission board, and inboxes are how sessions communicate. Every session reaches them directly at the top of its connected folder — no path guesswork, no navigating "up," no special cases.

05The Six Features

🧠

Team Building

The Overmind interviews you about your role and proposes 5–8 AI specialists tailored to your actual work. Each gets a human name, a defined domain, a bootstrap file, a persona file, and an inbox. Approve the team and it builds one team-root folder with shared state at the top and a subfolder per specialist. Every project — Overmind and specialists — connects that same root; identity comes from Project Instructions.

📡

Handoffs

Sessions have limited memory. At the end of any session, ask for a handoff — the Overmind writes a structured brief of what was done, what's in progress, and what's next, then gives you a passphrase. Say it at the start of your next session and the Overmind activates fully briefed. It proactively offers handoffs at natural stopping points.

🎯

Dispatch

Send work to a specialist without explaining everything from scratch. The Overmind writes a mission brief to the specialist's folder, snapshots your open browser tabs, and gives you a passphrase. Open the specialist's session, say the phrase — they activate ready to work. Any session can dispatch, not just the Overmind.

👥

Splinter Twins

Not everything deserves a mission brief. For a quick question, review, or small draft in a specialist's domain, the Overmind spawns a temporary in-session twin that hydrates from the specialist's own files, works in their voice, reports back signed "[Name] (twin)", and dissolves. The real session is untouched.

"Create a token copy. It gains haste. Sacrifice it at the beginning of the next end step."

🗂️

Mission Board

MISSION_BOARD.md is the single live view of everything in flight — one row per mission with assignee, status (PENDING → ACTIVE → COMPLETE, plus BLOCKED), and dependencies. Dispatchers add rows, specialists update their own, polling tasks reconcile drift. Ask "what's in flight?" anytime.

📬

Inboxes

The tier below dispatch. Team members leave short notes in each other's INBOX.md — a finding, a heads-up, a correction — with zero ceremony. Every session checks its own inbox at startup and surfaces unread notes in one line. Urgent work still goes through dispatch.

Team building runs once at setup. Handoffs are each session's save-game — same passphrase mechanic, pointed at itself.
Want to see any of this with your own work in it? Ask your Overmind: "give me a real-world example of how dispatch works" (or twins, the board, inboxes, handoffs). It will walk you through a full scenario built from your actual role, team, and deadlines — much better than generic docs.

07How the Passphrase System Works

Everything runs on passphrases. The Overmind writes a brief, invents a passphrase, and tells you what it is. You say the phrase to the right session — it activates fully briefed. You never write or touch a file. The Overmind handles all of it.

Phrases are scoped to the mission: a solo dispatch gets a phrase in that specialist's voice, and a mission spanning several specialists gets one shared operation codeword. For group ops you don't even need the codeword — open each session and type /go; the phrase remains as the fallback.
